01 / THINKING

Language models do not have memory

A language model takes input text and returns output text. Chat tools imitate memory with a sliding window or a summary of older messages. When conversations grow, earlier design rules drop out of context and large edits break unrelated code.

Chat-Based File Editing Unbounded Context

The model reads entire files and rewrites both logic and module wiring in one pass.

Context limits force implicit truncation. You review large diffs to find which invariant changed or which dependency broke.

Explicit Graph and Small Units Explicit State

Slate stores each function, test case, intent, and wire in plain JSON under slate/. You and the architect model inspect the exact inputs sent to each generation step.

Each atomic node is constrained to 60 lines or less. Code above that level is a visual flow graph compiled deterministically into source files.

02 / STRUCTURE

Files inside a Slate project

A Slate workspace keeps code units, flow wires, canvas layout, and project settings in separate JSON files. Editing layout positions does not modify code files.

slate/nodes/**/*.json JPL-60
Stores one atomic function, class, or prelude block per file. Holds imports, typed signature, intent, contract, test cases, checks, and raw code bounded to <= 60 lines.
slate/flows/**/*.json Deterministic
Stores typed inputs, outputs, call instances, data wires, and control regions (branch, foreach, repeat). The compiler turns each flow directly into a function.
slate/layout.json Visual Only
Stores canvas node positions, map positions, placeholders, and attached board notes. Semantic code indices ignore layout changes.
slate/slate.json Zero Secrets
Stores project name, target language, compile output path, library references, and optional LLM endpoint or env var name. Raw API keys on disk are rejected.
03 / TWO-TIER AI

Separate architecture from implementation

Slate splits software work between a frontier architect model and a smaller coder model. The frontier model designs contracts and wiring without writing function implementations.

Attribute Tier 1: Frontier Architect (MCP) Tier 2: Component Forge (HTTP)
Interface Model Context Protocol (slate_mcp_server.js) OpenAI-compatible HTTP SSE (llama.cpp, Ollama, OpenRouter)
Responsibility Search units, place notes, pan camera, define typed stubs, wire flows, trigger batch forge, compile project Implement <= 60-line function body and matching unit test for one atomic stub
Code Restriction Zero function bodies (slate_define_stub rejects body code) Single function scope; cannot import internal slate.* paths or redefine listed dependencies

04 / SCOPE

Supported languages and unbundled runtimes

Slate does not bundle a model server. Connect your own local inference binary or remote HTTP endpoint, then port, forge, or compile supported targets.

Language and Verification Support Multi-Language
  • Python: AST parsing on Lezer, Two-Tier batch forge, Pydantic strict validation, pytest, flow execution preview, port, and compile.
  • TypeScript / JavaScript: TypeScript Compiler API parsing, Two-Tier batch forge, strict tsc typecheck, isolated Node check runner, port, and compile.
  • C#, C++ / Arduino: AST parsing, JPL-60 checks, project porting, and deterministic compilation without automated per-node forge test loops.
  • Prose: Passage, citation, section, and rubric ports, budget/citation contract checks, and Markdown (.md) or LaTeX (.tex) compilation.
Unbundled Inference Endpoint OpenAI-Compatible

Run llama-server or Ollama locally, or configure OpenRouter with an environment variable name in slate.json (default port http://127.0.0.1:8080/v1):

llama-server --model Qwen3-Coder-30B-A3B.gguf --port 8080 --ctx-size 4096 --n-gpu-layers 99

Tested benchmarks (Scientific Calculator 2-wave and MRV Sudoku 4-wave specs): 9/9 forged stubs in 1 batch with 0 Frontier implementation lines on both qwen/qwen3-coder-30b-a3b-instruct and google/gemma-4-26b-a4b-it.

05 / INSTALL

Install the extension or ask an agent

Build and install the VS Code extension manually, or copy the setup instruction below for your AI coding agent. See README.md for full details.

Manual Build and VSIX Install CLI

Requires Node.js >= 20, Python 3.10+ with pytest and pydantic, Playwright Chromium (for launch gate), and VS Code code CLI.

git clone https://github.com/range-et/slate.git
cd slate
npm ci
npm ci --prefix vscode-extension
npx playwright install chromium
npm run package-extension -- --install
Prompt for Your AI Agent MCP + VSIX

Give this instruction to Claude Code, Cursor, Codex, Antigravity, or Gemini CLI to install Slate and connect its MCP server to your workspace:

Clone https://github.com/range-et/slate.git (or pull main if present), install root and vscode-extension npm dependencies, build the webview and extension (or run `npm run package-extension -- --install` to install the VSIX into VS Code), verify `node vscode-extension/out/mcp/slate_mcp_server.js --workspace . --list-tools`, and register that server command in my MCP config with `--workspace` pointing to my current project directory.
