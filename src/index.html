The Mental Model

Grasshopper where you forge atomic components

Traditional LLM coding environments trap developers in sprawling chat windows, sliding-context drift, and 1,000-line monolithic diffs where errors cascade. Slate flips this paradigm.

The Flaw of Chat-Driven Monoliths Status Quo

LLMs are stateless predictors. Sliding context windows forget early architectural invariants. When asked to edit large files, models rewrite glue code, reintroduce regression bugs, and hallucinate dependencies.

Developers spend more time refereeing AI diff conflicts than composing clean software architectures.

The Slate Formulation Slate

Atomic Library Units (`slate/nodes/**/*.json`): The only place where raw code lives. Strictly bounded by JPL-60 (≤60 lines, typed signatures, Pydantic contracts, pytest, and mutmut mutation tests).

Compositions & Flows (`slate/flows/**/*.json`): Everything above 60 lines is a visual graph. Instances connect through typed ports. Compilation to Python is 100% deterministic — no generative model guesses glue code.

Architectural Pillars

Engineered for Verifiability

Slate enforces constraints that make automated verification mathematical rather than probabilistic.

1. JPL-60 Discipline ≤60 Lines
Inspired by NASA JPL's Rules for Safety-Critical Code. Every function node is constrained to ≤60 lines of code, explicit parameter and return type annotations, bounded loops, and strict Pydantic contract validation.
2. Flow Composition Deterministic
Programs are graphs of atomic instances wired together. The compiler deterministically generates runtime Python modules directly from flow graphs (`flowToNode`), eliminating hallucinated integration code.
3. Two-Tier Labor Architect / Forge
Frontier models act as spatial architects via the Model Context Protocol (MCP), designing stubs and wiring graphs. Local LLMs act as component blacksmiths, forging 60-line bodies from 600-token packets.
4. Verified Candidates Guardrails
Generated code is never blindly accepted. Candidate implementations undergo automated pytest checks and mutmut mutation tests. Candidates are inspected, iteratively revised, or instantly reverted.
Two-Tier AI Division of Labor

Frontier Architect vs. Local Forge

Slate cleanly separates high-level architectural reasoning from local code synthesis.

Privacy & Extensibility

Unbundled Local LLM Architecture

Slate is not bundled with a heavy LLM server. You bring your own local model, runtime, and hardware acceleration.

Many AI developer tools force you to download gigabytes of pre-packaged runtimes or require proprietary cloud subscriptions. Slate takes the opposite approach:

  • Zero Server Bloat: The VS Code extension and web canvas are lightweight, running natively on Lezer and React.
  • Any OpenAI-Compatible Engine: Connect to llama.cpp (llama-server), Ollama, LM Studio, vLLM, or any local inference server.
  • Architect-Configured: Your frontier model or agentic assistant configures and monitors the local forge endpoint on demand.
  • 100% Offline & Private: Atomic code generation never leaves your workstation unless you choose to use a remote endpoint.
# Example: Start local llama.cpp forge server
llama-server \
--model Qwen2.5-Coder-7B-Instruct.Q4_K_M.gguf \
--port 8080 \
--ctx-size 2048 \
--n-gpu-layers 99
# Slate automatically connects to http://127.0.0.1:8080/v1
