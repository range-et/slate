# Slate Plan — a node canvas for composing Python

Status: active — revised 2026-10-13 (decoupled `slate/` folder adopted).
Replaces the 2026-09-23 "source-first harness" plan. Shipped work is in
[features.md](features.md); tasks are in [issues.md](issues.md).

## North star

One large canvas per project where Python functions are nodes with typed
ports, wires carry values, and you compose freely — the way Grasshopper,
Blender Geometry/Shader Nodes, or Unreal Blueprints feel. You (or a local
llama.cpp model) write the small leaf functions; you wire them together by
hand; groups of wired nodes become real Python functions; values flow through
the graph live so you can see what every node does.

The local model is a helper for writing one node's body. It is never the
driver.

## Why it does not click today

Audit of the shipped harness (2026-10-13). The problems are structural, not
polish.

1. **The canvas is a file browser, not a composition surface.** Nodes are laid
   out as files → classes → functions and are clamped inside their parent
   container (`extent: 'parent'` in `src/harness/graph.ts`). You can't put two
   functions from different files next to each other, so there is no "one
   large workspace."
2. **Ports are fake.** Every node draws input/output handles, but
   `nodesConnectable={false}`. The core gesture of every node tool — drag a
   wire — does nothing.
3. **The only wire means "include in the LLM prompt."** Context edges
   (`depends-on`) are prompt plumbing, not dataflow. There is no way to
   express "the output of A feeds B."
4. **Code lives off-canvas.** Every single click opens the source in a side
   editor, so clicking to drag or inspect moves your editor. The node shows
   only a signature, and the inspector is a form with separate Save buttons.
5. **Two competing input languages.** An uppercase CAD command line with `::`
   separators (`STUB file.py :: def f(x: int) -> int :: intent`) next to mouse
   menus. Any printable key typed on the canvas is hijacked into that command
   line. Context is picked from a `<select>` dropdown.
6. **No creation gesture.** You can't double-click or Tab on the canvas to add
   a node, and can't drag from a port to create the next one. Creating a
   function means typing a `STUB` command.
7. **Nothing runs.** Grasshopper and Geometry Nodes work because you change
   an input and see every downstream value update. Slate never executes code,
   so the graph never shows behavior.
8. **Notes are dead text.** They can't stand in for a function, jump to it,
   or become one.
9. **The canvas fights you.** Every drag rewrites and saves the whole
   `.slate.json`, which triggers a re-index, a new revision, and a full graph
   rebuild. Every keystroke in any Python file bumps the revision, so commands
   issued meanwhile fail with "graph changed; run the command again."
10. **The examples don't use the current grammar.** Calculator and tic-tac-toe
    still use the legacy annotation format, so they show up as provisional,
    intent-less nodes. Slate also can't map its own TypeScript code, so
    dogfooding it on this repo shows nothing useful.
11. **The previous plan ruled this direction out.** It said "the graph is not
    the product," deferred call graphs, and gated further work on a week-long
    pilot. The interaction feels off because the product was steered away
    from composition.

## Core model

### Workspace format: a decoupled `slate/` folder of JSON

Decided 2026-10-13. The `slate/` folder is the source of truth, and it holds
JSON only: one file per node, plus files that refer to nodes by ID. `src/` is
generated by **Compile**. The canvas is the editor and these files are its
save format, as in Blender or Unreal.

```diagram
my_project/
├── slate/
│   ├── slate.json              name, default language, compile target
│   ├── layout.json             positions, notes, refs, frames (canvas only)
│   ├── nodes/
│   │   ├── clamp.json          one node = one JSON file
│   │   └── scoring/
│   │       └── normalize.json  subfolder = output module scoring.py
│   └── flows/
│       └── score_pipeline.json nodes + wires, referring to node IDs
├── .slate/build/               runner output (gitignored)
└── src/my_project/             generated by Compile; do not edit
```

**Node files** (`slate/nodes/**/*.json`). The node ID is the path without
`.json` (e.g. `scoring/normalize`), and `name` must equal the file name.

```json
{
  "slate": 3,
  "name": "normalize_score",
  "intent": "Convert a score to an integer percentage from 0 through 100",
  "contract": "Raise ValueError when maximum is not positive",
  "context": ["clamp"],
  "examples": ["normalize_score(50, 200) == 25"],
  "describedBy": "human",
  "locked": false,
  "imports": ["import math"],
  "code": [
    "def normalize_score(score: int, maximum: int) -> int:",
    "    if maximum <= 0:",
    "        raise ValueError(\"maximum must be positive\")",
    "    return clamp(score * 100 // maximum, 0, 100)"
  ]
}
```

- `code` holds exactly one definition, stored as a list of lines so git diffs
  stay line-by-line. Ports come from parsing its signature and are never
  duplicated in JSON.
- `context`, flows, and layout refer to other nodes by ID. Calls between
  nodes need no imports: Compile and the runner resolve node names and add
  them. `imports` lists only external modules.
- `language` defaults to `slate.json`'s `language` (`python`). Each language
  gets an adapter (parse signature → ports, validate a candidate, emit
  compiled code), so the format can later carry C# or other languages without
  changing the canvas.
- Unknown keys are preserved on write. Serialization is deterministic.

**Ownership:**

| Thing | Owned by |
| --- | --- |
| Node code and metadata | `slate/nodes/**/*.json` |
| Composite wiring | `slate/flows/*.json`; Compile generates the function |
| Positions, notes, refs, frames | `slate/layout.json` (never touches node files) |
| Output package | `src/…`, generated and overwritten by Compile |
| Existing, non-Slate code | Read-only **library**, indexed and callable as nodes |
| Live values | Runtime only, never persisted |

Why this layout:

- **Small, structured files.** Readable diffs, easy merges, and metadata is
  plain fields instead of a comment grammar. Dragging never rewrites a node.
- **No in-file patching.** The model rewrites one node's `code`, so the
  annotation grammar, ID adoption, and range-confined patching inside user
  modules go away.
- **Language-agnostic.** The canvas, flows, layout, and porting pipeline only
  see JSON. Languages differ only in their adapter.
- **Free porting.** Loading an existing project is mechanical (see Porting).

Costs and mitigations:

- Node code isn't a file the editor's language server sees. The canvas
  carries a CodeMirror editor per node. "Open in editor" can later open a
  temporary source buffer that syncs back on save.
- Running and debugging happen on generated code. The runner writes to
  `.slate/build/` and Compile writes to `src/`. Every block is stamped
  `# slate: nodes/<id>`, and tracebacks map back to nodes.
- Hand edits to `src/` are overwritten. Generated files say so, and an
  explicit **Eject** hands a module back to plain code.
- Renames touch references. Rename is a host action that moves the file and
  updates every referring JSON in one edit.

### Porting existing projects (micro-context descriptions)

A traditional Python project becomes a Slate project mechanically:

1. **Split.** The importer walks the project with the TypeScript adapter.
   Every top-level function and class becomes a node JSON carrying only the
   external imports it uses. Calls to other functions resolve as node
   references. Module-level state and anything that can't be split cleanly is kept as a read-only
   library module and reported. Nothing in the original project is modified.
2. **Describe.** A local model then visits every node, leaves first. Each
   request is microscopic: one function's source, plus the signatures and
   intents of the nodes it calls, and nothing else (a few hundred tokens). The
   model returns one `intent:` line and an optional `contract:` line. Small
   llama.cpp models handle this well because the context never grows.
3. **Resume and review.** Nodes that already have an intent are skipped, so a
   stopped run resumes for free. Generated lines are marked
   `described-by: llama` until a human edits them.
4. **Prove.** Compile the ported project and run its original test suite
   against the output. A port is done when those tests pass.

### Node kinds

```diagram
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ Function     │  │ Reference    │  │ Placeholder  │  │ Flow (group) │
│ the real def │  │ alias of a   │  │ name only,   │  │ wired subgr. │
│ ports from   │  │ function;    │  │ dashed; can  │  │ → generated  │
│ signature    │  │ many allowed │  │ become node  │  │ Python def   │
└──────────────┘  └──────────────┘  └──────────────┘  └──────────────┘
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ Input        │  │ Viewer       │  │ Zone         │  │ Note         │
│ number/text/ │  │ shows value  │  │ repeat /     │  │ free text    │
│ list/example │  │ on a wire    │  │ for-each /if │  │ (existing)   │
└──────────────┘  └──────────────┘  └──────────────┘  └──────────────┘
```

- **Ports** come from the signature the adapter already extracts
  (`parameters`, `returnAnnotation`). Inputs on the left, return on the right,
  colored by type annotation; untyped is grey "any". Mismatches are warned,
  not blocked.
- **Reference nodes** are what you asked for as reference notes: a compact
  pill showing a function's name and ports that can sit anywhere, as many
  times as you like. Right-click → Go to definition, Find references, Select
  definition node, Generate body.
- **Placeholders** are shortform notes: type a name (and optionally a
  signature). If the name resolves, the placeholder becomes a reference. If it
  doesn't, right-click → **Create node** writes a new node file, with its
  signature inferred from the wires attached to it.
- **Flows** are Blender node groups / Grasshopper clusters: select nodes,
  Ctrl+G, name it. Tab enters; breadcrumbs exit. Group Input/Output nodes
  define the signature.
- **Zones** cover loops: for-each compiles to a list comprehension or `for`,
  repeat carries state N times, branch compiles to `if`.

### Two views of one project

- **Compose** (default): the free canvas above. Files are not containers.
- **Map**: nodes grouped by `slate/nodes` folder (= output module) for
  orientation. The same tree, plus read-only library code, lives in a
  **Library** sidebar; drag from it to the canvas to drop a reference.

### Interaction grammar (one way to do each thing)

| Gesture | Effect |
| --- | --- |
| Click | Select only; no editor jump |
| Double-click node | Expand inline code (CodeMirror on the node) |
| F12 / Cmd-click / menu | Go to definition in the side editor |
| Double-click canvas, Tab, Shift+A | Add-node search at the cursor |
| Drag port → port | Wire |
| Drag port → empty space | Add-node search filtered by type, auto-wire |
| Ctrl+Shift+click | Attach a viewer to this node's output |
| Ctrl+G / Tab / Esc | Group into flow / enter / exit |
| M / H | Mute (bypass) / collapse |
| Cmd+K | Command palette (replaces the uppercase command line) |
| Right-click | Context menu; every menu item is also in Cmd+K |

Every gesture dispatches the same typed action. Typed actions are never
converted to command strings and re-parsed.

### Live evaluation

In a trusted workspace, with **Live** toggled on, the extension host runs a
small runner in the workspace's Python interpreter. The runner materializes
nodes into `.slate/build/` (no full Compile needed), evaluates the active flow in topological order, and returns a
truncated `repr` for every wire plus exceptions per node. Changes are
debounced and every run has a timeout. Inputs come from Input nodes or
`example:` metadata. This is the Grasshopper moment, and it also gives
the local model an oracle.

### The local model's role

"Generate body" on a function or placeholder builds a packet automatically
from what the canvas already knows: the signature (from ports), intent, wired
upstream/downstream neighbors, explicit context, and example values flowing
in. The candidate is run against the examples **before** review. A bounded
"iterate until examples pass" loop (at most 3 attempts) shows every attempt.
Confinement, review, accept, and undo stay as shipped.

## Safety contract

1. Node JSON files and their dirty buffers are authoritative. The webview never
   writes files; it sends typed intent to the extension host.
2. The extension host owns filesystem access, indexing, Compile, the runner,
   llama.cpp transport, proposals, and `WorkspaceEdit` application.
3. Every node mutation (new node, metadata edit, code edit, generated body,
   generated flow, port) is bound to the target node's code hash, applied as one
   `WorkspaceEdit`, and undoable. Layout writes are plain file writes.
4. Staleness is checked per affected node file, not per global revision.
5. Code runs only in trusted workspaces, only when Live is on, and only with a
   timeout. There is no cloud fallback.

## Phases

Each phase has a "you can feel it" exit test. Dogfood every phase on a real
project.

### Phase 0 — cleanup (done 2026-10-13)

Removed the dead LibCST engine and its contract. Moved the legacy notebook to
`legacy/` (Pages still deploys it; S-001 deletes it later).

### Phase 1 — `slate/` folder and a calm canvas

`slate/` loader (slate.json, layout.json, node JSON). Free canvas where every
node is one node with no file containers. Click selects only. No keystroke
hijacking. Layout lives in layout.json and never triggers a re-index. New node
from the canvas. Intent, contract, context, and code are edited in the
workbench (CodeMirror) and written to the node JSON. New Project creates a
`slate/` folder. llama_demo is converted. Then: a Cmd+K palette replaces the CAD command line,
a single shared protocol type file, inline intent editing, a searchable
context picker, and drag-a-wire context.
**Exit:** an hour in the canvas without fighting it.

### Phase 2 — port and compile

Importer (split → node JSON + library leftovers). Micro-context description
pass with resumable progress. Compile `slate/` → `src/` with import
rewriting and source stamps. Retire the old project-v2/`## @slate` annotation
mode.
**Exit:** port calculator and tic-tac-toe, compile them, and their original
tests pass.

### Phase 3 — one workspace: references, placeholders, library

Library sidebar (folders + read-only library code), reference nodes,
placeholders → new nodes, find references, Compose/Map toggle.
**Exit:** describe a function once, drop it anywhere, jump to it from anywhere.

### Phase 4 — ports, wires, flows

Typed ports, port-to-port wires, add-node search from canvas and ports,
Ctrl+G flows saved to `slate/flows/*.json`, deterministic codegen in Compile,
Tab into flows.
**Exit:** build a four-node pipeline from existing nodes without typing
Python and get a real Python function out of Compile.

### Phase 5 — live values

Input/Viewer/Example nodes, trusted runner over `.slate/build`, per-wire
previews, per-node errors, mute/bypass, auto-solve.
**Exit:** change a number and every downstream value updates in under a
second.

### Phase 6 — local model writes leaves inside the graph

Graph-derived packets, examples run before review, bounded iterate-until-pass,
llama.cpp health, edit/regenerate candidates.
**Exit:** sketch a placeholder between two wired nodes, generate it, watch it
pass its examples, accept, undo.

### Phase 7 — zones and control flow

For-each, repeat, and branch zones compile to Python.
**Exit:** the tic-tac-toe game loop is expressible as a flow.

### Later

Ruff/Basedpyright validation; generate-all as "fill every placeholder in a
flow in topological order"; reverse codegen (straight-line function → flow);
methods and classes as first-class compose nodes; a second language adapter (e.g. C#).

## Open questions

- **Class granularity.** Start with one node file per class; add per-method
  ports later.
- **Interpreter selection.** Use the Python extension's active interpreter
  when present, or a `slate.python.path` setting otherwise.
- **`src/` in git.** Recommended: commit the compiled output so the project
  stays usable without Slate; Compile is deterministic, so diffs stay honest.
- **Host.** Stay in VS Code (files, undo, interpreter, editor) but give the
  canvas the full editor area.
